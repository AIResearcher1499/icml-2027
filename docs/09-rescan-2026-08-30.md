## Open candidates (not locked)

Rank is a probe order, not a lock. Deep-sweep the chosen one before GPU.

### R1 — The Check Trap (preferred)

**Assumption.** A self-check / verifier pass *filters* generator traces to a more reliable subset. Test-time “think then verify” enlarges the trusted set.

**Claim.** The verifier is a Flexibility Trap: it skips high-entropy disagreement with the generator and **swaps** the solved-item set. `G` = items the generator gets right (pass@n). `V` = items the same model *accepts* after a verify prompt (or accept/reject each of n traces). Prediction: `|G∖V|` large (false reject of unique-correct traces) and `|V∖G|` non-empty (false accept of unique-wrong). Not mean accuracy of “check your work.”

**Why not P1.** P1 was *external gold text*. This is a *second decode* as a channel, no retrieved evidence.

**Why not CoVerRL.** They train a generator–verifier loop against majority-vote collapse. We measure a **frozen** 8B, solved-set Venn, inference only.

**Why not process-vs-outcome.** Those papers change the *reward*. We do not train.

**Quantities.** Unbiased pass@k of generator; accept-rate of verifier; Venn `|G∖V|`, `|V∖G|`, `|G∩V|` on a primary band (generator pass@8 ≥ 0.5). Optional: entropy at the verify decision token.

**72h probe.** Qwen3-8B, 80 GSM8K + 80 Hotpot (reuse P1 item freeze if still on disk, or a new freeze). n=8 generate. For each item: verify-the-mode, or verify each trace (cheaper: verify mode only for smoke). LIVE: `|G∖V| ≥ 2|V∖G|` and excess ≥ 5. KILL: V ⊇ G, or only mean accuracy of checked answers moves, or verifier is random.

**Fit.** Inference. Same stack as P1/P2. Strongest leftover Flexibility Trap DNA on an NLP object (the language of checking).

**Risk.** “Check your work doesn’t help” is an old ACL observation. The paper dies if we only show mean accuracy. The Venn is the claim.

### R2 — The Choice Trap

**Assumption.** Multiple-choice / candidate lists *help* by constraining the output. More options = more flexibility.

**Claim.** A candidate set is false flexibility: it lets the model skip the high-entropy *generation* fork (the name, the number, the proverb ending). The generate-only solved set is not a subset of MCQ. `|G∖M| ≫ |M∖G|`.

**Why not ProverbIT.** They showed complete-vs-choose on Italian proverbs. We need a **mechanism** (fork skip under options) on mixed math+QA, plus entropy at the answer span with vs without options — not a new proverb benchmark.

**72h probe.** Same items as open generation and as 4-way MCQ (gold + 3 model-sampled distractors, frozen). n=8. LIVE: coverage Venn as in R1, plus mean entropy of the answer-span first token **drops** under MCQ. KILL: only accuracy of MCQ > generate (the default), or entropy does not drop.

**Fit.** NLP-native. ACL fallback is easy. ICML only if the fork-entropy + Venn is the headline (Flexibility Trap of *menus*).

**Risk.** Format-artifact papers are thick. Easy to become “MCQ is easier.”

### R3 — Strategy coverage, not answer coverage (backup)

**Assumption.** Self-consistency / majority vote recovers the model’s knowledge.

**Claim.** Majority vote deletes *correct strategies that are not the mode*. Item-level pass@k can look fine while the set of *distinct correct traces* collapses to one template. Quantity: number of distinct correct traces (normalized AST / equation skeleton / entity chain) under majority vs under union.

**Why dangerous.** Blend-ASC / Invisible Leash / 2605.17026 already own answer-level coverage. This only lives if **strategy** clustering is pre-registered and not retuned. Heavier annotation.

**72h probe.** Only if R1 and R2 die. GSM8K skeletons only (no Hotpot). LIVE: majority unique-strategy count ≤ 0.5 × union unique-strategy count, with ≥ 20 items in the band. KILL: only pass@1 vs pass@8 (Invisible Leash replica).
